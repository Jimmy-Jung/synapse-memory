# 필요한 사실을 찾는 인터뷰

작성자: JunyoungJung · 작성일: 2026-09-22

질문 수·라운드 수·프로젝트 수는 고정하지 않는다. 관련 재료가 있으면 곧바로 초안을 쓰고, 새로운 답변이 글의 의미를 바꿀 때 추가 질문한다. 한 번에 대답하기 쉬운 주제로 묶고 답을 기다린다.

| 부족한 재료 | 질문 예시 | 답변 후 구분할 것 |
| --- | --- | --- |
| 정체성 | 반복해서 맡거나 즐겨 해결한 문제는 무엇인가요? | 실제 사례가 있는 주장과 희망하는 이미지 |
| 맥락·책임 | 당시 무엇이 문제였고, 그중 어느 부분을 맡았나요? | 팀 전체 과제와 개인 권한·담당 범위 |
| 판단 | 다른 방법도 있었는데 이 방법을 택한 이유가 있나요? | 사용자의 실제 이유와 사후 추정 |
| 행동 | 직접 바꾸거나 결정한 부분을 설명해주세요. | 개인 작업과 공동 결과 |
| 결과 | 적용·출시·운영 중 어디까지 확인됐나요? | 구현 완료, 운영 효과, 이후 계획 |
| 수치 | 무엇을 언제 어떤 표본·환경에서 비교했나요? | 관측값, 추정값, 목표, 재현 가능한 조건 |
| 태도 | 그 경험에서 앞으로도 지키고 싶은 기준이 생겼나요? | 사용자가 말한 가치관과 모델의 해석 |

자기소개에서는 동기와 태도를 설명하는 데 충분한 경험을 찾는다. 이력서에서는 회사·기간·역할과 주요 기여의 범위를 먼저 정리한다. 자료에 없는 필수 항목만 묻고 연락처·학력·취미를 모든 문서에서 의무 수집하지 않는다.

사용자가 '팀에서 했다'고 답하면 본인이 맡은 부분을 확인한다. '잘 모르겠다'면 측정치를 강요하지 않고 확인 가능한 적용 상태를 묻거나 해당 성과를 제외한다. 일부만 완료했다면 나머지를 끝낸 것으로 표현하지 않는다.

자료가 전혀 없다면 우선 어떤 일을 해왔고 어떤 글에 쓰려는지부터 묻는다. 핵심 재료가 없는 상태에서 빈 경력 양식이나 상상한 자기소개를 완성본처럼 만들지 않는다. 확보한 내용이 생기면 확인 목록과 함께 작성 단계로 넘어간다.
