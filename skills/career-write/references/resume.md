# 서술형 이력서: 책임·판단·행동·결과

작성자: JunyoungJung · 작성일: 2026-09-22

## 구조와 깊이

이름·직무·공개 연락처와 대표 링크 → 짧은 소개 → 최근 경력부터 회사·직책·기간 → 주요 기여 → 관련 추가 활동 순서로 시작한다. 개인 웹사이트나 상세 경력기술서에는 맥락과 판단을 충분히 쓰고, 지원 양식·페이지 제한이 있으면 그 조건을 우선한다.

회사별 도입에서 당시 제품·조직의 상황과 본인의 책임 범위, 중요한 제약을 설명한다. 회사 소개나 규모를 자신의 성과처럼 쓰지 않는다. 같은 회사에서 역할이 크게 달라졌으면 직책과 기간을 나눈다.

주요 기여는 의미 있는 주제명 아래 **상황 → 판단 → 직접 한 일 → 확인된 결과**가 이어지게 쓴다. 모든 항목을 STAR 네 제목으로 쪼개거나 같은 배경을 반복하지 않는다. 관련된 행동은 한 흐름으로 묶고 다른 프로젝트는 분리한다. 회사 내 항목은 중요도·지원 관련성을 우선하되 이해에 필요한 시간 순서는 보존한다.

## 문장

- 핵심 기여를 먼저 쓰고 설계 판단과 이유, 구현·협업, 결과나 현재 상태를 연결한다. 기술명 뒤에는 그 기술이 해결한 문제를 설명한다.
- '주도했다'는 실제 의사결정·실행 범위가 확인될 때 쓴다. 일부를 맡았다면 담당한 부분을 명시한다. 팀의 출시는 팀 결과로, 자신의 설계·구현은 개인 기여로 구분한다.
- 목표·기대 효과와 관찰된 결과를 구분한다. 전환 중인 프로젝트는 완료한 경로와 남은 범위를 보존한다. 아직 효과를 측정하지 않았다면 구현·적용 사실까지만 쓴다.
- 수치에는 가능한 범위에서 전후 값, 측정 대상·기간·표본·환경을 함께 둔다. 자료에 없는 측정 조건이나 개선율을 계산해 사실처럼 보충하지 않는다.
- 자부심이나 배움은 구체 경험과 연결한다. 임원 경력·조직 규모·감상 문단을 억지로 따라 하지 않는다. 현재 책임과 완료된 일의 시제, 종결어를 일관되게 맞춘다.
- 학력·자격·직책·연락처는 실제 자료만 사용한다. 기술 목록과 추가 활동은 본문 경험을 이해하는 데 필요한 것만 넣는다.

## 가상 수정 예시

다음은 규칙 설명용이며 사용자의 경력 근거가 아니다.

> 수정 전: 새로운 아키텍처를 도입해 성능과 생산성을 크게 높였습니다.
>
> 수정 후: 화면 로직과 요청 처리가 결합되어 오류 흐름을 테스트하기 어려웠습니다. 요청 처리를 분리하고 서버 연결 없이 오류 처리를 검증할 수 있도록 변경했습니다.

확인된 변화만 적고 측정하지 않은 성능·생산성 효과를 덧붙이지 않는다.

## 확인

회사·직책·기간을 찾기 쉬운지, 책임 범위와 실제 행동이 드러나는지, 판단의 이유와 결과를 이해할 수 있는지 확인한다. 팀 성과·개인 기여, 목표·실적, 완료·진행을 구분하고 모든 수치가 그 근거 범위를 넘지 않는지 검토한다. 제출 본문에 가상 사례나 미확인 표시를 남기지 않는다.
