# 회사 조사와 경험 매칭

작성자: JunyoungJung · 작성일: 2026-09-22

## 조사 범위

JD 요약에서 끝내지 않는다. 지원 포지션을 이해하는 데 필요한 회사·제품·기술·조직 맥락을 찾는다. 모든 회사를 같은 분량의 시장 보고서로 만들지는 않는다.

- 공식 홈페이지·제품 자료: 고객과 해결하는 문제, 사업 방식, 해당 제품의 역할.
- 공식 채용공고: 포지션, 주요 업무, 필수·우대 요건, 근무 조건·제출 문항 중 작성에 필요한 부분, 게시·마감 상태.
- 기술 블로그·공개 저장소·발표: 지원 분야에서 실제 드러나는 기술과 개발 방식. 오래된 글의 기술을 현재 팀 전체의 스택으로 단정하지 않는다.
- 공식 뉴스·IR·제품 업데이트: 최근 변화 중 지원 역할에 영향을 줄 내용. 게시 날짜와 사건 날짜를 구분하고 사실 주장에 직접 출처를 붙인다.
- 문화·인재상: 회사가 제시한 기준과 관찰된 사례를 구분한다. 직원 후기 등 보조 자료는 개인 관찰로 표시하고 회사 전체의 사실로 일반화하지 않는다.

사용 가능한 웹 검색·페이지 읽기 도구를 사용한다. 특정 MCP·브라우저·유료 provider를 필수로 설치하거나 현재 에이전트 밖의 합성 작업을 자동 실행하지 않는다. 검색·읽기만으로 조사하며 계정 생성·지원서 제출·채용 담당자 연락은 포함하지 않는다.

## 근거와 추론

비자명한 회사 주장에는 직접 뒷받침하는 URL과 확인일을 남긴다. 회사가 발표한 수치는 회사 발표임을 구분한다. '이 공고가 실제로 중요하게 볼 것' 같은 해석에는 근거 문구와 **추론** 표시를 붙인다. 지원자 경험의 사실 근거는 회사 자료가 아니라 경력 원자료나 사용자 답변이다.

검토 자료의 매칭 표에는 다음을 담는다.

| 항목 | 기록 |
| --- | --- |
| 요구사항 | 공고나 공식 회사 자료의 요구와 출처 |
| 관련 경험 | 경력 원자료와 본인이 실제 맡은 행동 |
| 매칭 정도 | 직접 경험 / 인접 경험 / 공백과 그 이유 |
| 본문 반영 | 강조할 위치와 설명할 연결, 또는 제외 이유 |

규모·매출·제품 출시 같은 회사 성과를 지원자 개인 성과로 전환하지 않는다. 회사가 원하는 가치관을 사용자의 신념으로 만들어 넣지 않는다.

## 공고 없음·접근 실패

- 공고가 없으면 공식 채용 페이지에서 사용자가 지정한 역할에 맞는 공고를 찾는다. 서로 다른 후보가 있다면 대상부터 확인한다.
- 공고를 찾지 못해도 회사와 목표 역할이 명확하면 조사 가능한 범위를 정리하고 **특정 공고 적합성이 미확인인 회사·역할 기준 초안**을 작성할 수 있다. 요구사항·우대 조건을 추정해 채우지 않는다.
- 사용자가 특정 공고에 대한 정확한 지원서를 원했는데 원문에 접근할 수 없다면 해당 공고 텍스트를 요청한다. 그동안 가능한 회사 조사는 진행하되 그 공고에 맞췄다고 주장하지 않는다.
- 웹 도구 자체가 없으면 기존 자료의 확인일과 부족한 조사 범위를 알린다. 이미 제공된 자료로 가능한 작업을 진행하고 현재 웹 확인을 했다고 쓰지 않는다.

취업 가능성·합격 확률을 점수로 만들어 보장하지 않는다. 경험 공백은 검토 자료에 남기고 실제로 갖춘 인접 역량을 설명한다.
